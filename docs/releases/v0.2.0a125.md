# BreadSched 0.2.0a125

Application version: `0.2.0a125`

Native schema version: `7`

Supported native schemas: `6–7`

This alpha fixes Plan totals that added amounts in another currency as if they
were in the reporting currency (issue #124).

## Highlights

- Schedules and transactions in another currency are converted before Plan adds
  them up. Each currency uses the latest exchange rate on or before the as-of
  date; a reverse rate is inverted when no direct rate exists.
- Plan states the rate used, its date and source, and whether it was inverted, in
  GTK, the web interface, print, and `breadsched activity`.
- When no rate applies, those amounts are left out of totals and listed
  individually. Previously 500 EUR plus 1,000 USD showed 1,500.00; now it shows
  1,000.00 and lists the 500 EUR until a rate is added.
- Category detail, the spendable-cash bridge, projected cash, and Expense
  Explorer's Remaining and rollover use the same converted amounts.
- `breadsched activity --as-of DATE` selects which rates apply.

## Native-book compatibility

No data-format change was made. Schema 7 books open directly; the supported
native compatibility window remains schemas 6–7.

## Upgrade and rollback

Keep an independent backup of a real book. This version does not migrate books;
older schema 7 builds can reopen them.

## Verified artifacts

After the complete CI matrix succeeds on main, the release workflow publishes
a source distribution, pure-Python wheel, and `SHA256SUMS` for the tested commit.
