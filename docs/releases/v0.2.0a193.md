# BreadSched 0.2.0a193

Application version: `0.2.0a193`

Native schema version: `10`

Supported native schemas: `6–10`

This alpha adds savings goals in every interface.

## Highlights

- A **savings goal** names an asset account, a target amount, a start date, and a
  target date. It works like a pending bill: from the start date, each income
  received sets aside a prorated share of what the goal still needs, so the
  whole target is set aside by the target date. Extra money can be allocated to a
  goal at any time; later income then spreads only the remaining gap. Income that
  never arrived sets nothing aside.
- What is set aside is an earmark, not the whole account. One savings account can
  hold money for several goals and for other purposes.
- The Dashboard holds goal earmarks out of **Available**, like bill reserves, and
  shows **Set aside for goals** on the desktop, in the browser, in the printout,
  and in `breadsched dashboard`. Money for a goal already in a non-cash account
  is held from spendable cash only for the part not yet moved there.
- The target date is a milestone: nothing is spent. Closing a goal (for example
  after the purchase) releases its earmark.
- The desktop **Savings Goals…** window, the browser **Goals** page, and the new
  `breadsched goals` command add, edit, fund, close, reopen, and delete goals. The
  Dashboard lists each open goal in a **Savings goals** table.
- New `breadsched migrate` brings a book from an earlier alpha to schema 10 on the
  command line, after writing a verified backup; read-only commands never migrate.

## Native-book compatibility

Native schema advances from 9 to 10: a new `savings_goal` table is added. Schema
10 books open directly; schemas 6, 7, 8, and 9 still migrate automatically with a
verified backup.

## Upgrade and rollback

Keep an independent backup of a real book. This version migrates schema 6
through 9 books to schema 10 on first open; earlier alphas (0.2.0a143 through
0.2.0a191) cannot reopen a schema 10 book afterward. Restore the pre-migration
backup to go back.

## Verified artifacts

After the complete CI matrix succeeds on main, the release workflow publishes
