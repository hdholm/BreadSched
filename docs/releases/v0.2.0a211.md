# BreadSched 0.2.0a211

Application version: `0.2.0a211`

Native schema version: `10`

Supported native schemas: `6–10`

This alpha publishes BreadSched for Linux as a Flatpak bundle, tested in its
sandbox with the desktop's file chooser and print dialog.

## Highlights

- Each release attaches `BreadSched-<version>.flatpak`, built from the released
  commit and installed and checked before it is published. Install it with
  `flatpak install --user BreadSched-<version>.flatpak`; its GTK runtime comes from
  Flathub. See **Install on Linux** in the desktop guide.
- Opening, saving, exporting, backing up, and printing in the Flatpak go through
  your desktop's own dialogs, and CI now exercises each of them through the real
  desktop portal.
- Books outside Documents work through the file chooser. BreadSched can reach only
  the book file itself there, so the backups it makes before upgrading or restoring
  are kept in `~/.var/app/org.breadsched.BreadSched/data/breadsched/beside-documents/`
  and the desktop says so. Correction: such a backup used to be lost as a hidden
  temporary file. Keep books in Documents where you can.
- The Flatpak's print dialog has no **Report** tab, so printing the Plan there first
  asks **Summary only** or **Include category detail**.
- `breadsched migrate` reports the backup it actually wrote.

## Native-book compatibility

No data-format change was made. Schema 10 books open directly; schemas 6, 7, 8,
and 9 still migrate automatically with a verified backup.

## Upgrade and rollback

Keep an independent backup of a real book. This version does not migrate schema 10
books, and 0.2.0a210 reopens them unchanged. Alphas before 0.2.0a193 cannot open a
schema 10 book; restore its pre-migration backup to go back.

Installing an older Flatpak bundle over this one downgrades the program only; books
are never touched.

## Verified artifacts

After the complete CI matrix succeeds on main, the release workflow publishes
a source distribution, pure-Python wheel, Windows installer, Flatpak bundle, and
`SHA256SUMS` for the tested commit.
