# BreadSched 0.2.0a255

Application version: `0.2.0a255`

Native schema version: `11`

Supported native schemas: `6–11`

This alpha records a storage decision; the application behaves as in 0.2.0a254.

## Highlights

- **Book storage stays as it is.** A measured comparison with fully normalized
  transaction and split tables found books 43% smaller but loading every
  transaction 1.5 to 1.7 times slower, so BreadSched keeps its current layout. The
  measurements and reasons are in the design decision record
  `docs/design/decisions/0001-transaction-storage.md`, and
  `scripts/storage_benchmark.py` repeats them.

## Native-book compatibility

No schema change. Schema 11 books open directly; schemas 6 through 10 migrate
automatically with a verified backup.

## Upgrade and rollback

Keep an independent backup of a real book. Going back to 0.2.0a254 needs no
restore; earlier alphas cannot reopen a schema 11 book.

## Verified artifacts

After the complete CI matrix succeeds on main, the release workflow publishes
a source distribution, pure-Python wheel, Windows installer, Flatpak bundle, and
`SHA256SUMS` for the tested commit.
