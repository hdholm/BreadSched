# BreadSched 0.2.0a308

Application version: `0.2.0a308`

Native schema version: `13`

Supported native schemas: `6–13`

This alpha brings the book server to `main`. One book can now be used from the
desktop, commands, and browsers at once, including a phone or tablet through a TLS
reverse proxy, by family members who each sign in with their own role.

## Highlights

- **Share a book.** `breadsched serve household.breadsched` holds a book; commands,
  browsers, and the desktop then use it through that server instead of stopping
  because the book is already open. The desktop can share the book it has open
  (**Preferences → Sharing**) and opens a book a server holds through it.
- **Family members and devices.** Used alone, nothing changes: no sign-in, no
  password. Give someone a user (`breadsched users add`) and a role in a book
  (`breadsched share`): owner, editor, viewer, or entry (adds transactions only).
  They sign in with their own password, and optionally a code from an authenticator
  app.
- **From a phone or iPad.** Behind a TLS reverse proxy (decision 0003 has an nginx
  configuration), the browser and the phone-sized **Quick entry** page reach the
  book; the server itself never listens beyond this computer.
- **Your own view.** The Plan's controls and the Dashboard's arrangement are each
  person's own, for each book.
- **Faster opening.** The desktop draws only the tab you were on and reads the
  heavier views in the background.
- **Smaller books.** Transactions are stored without keys at their defaults, about
  half the JSON.

## Command-line compatibility

- `due-review --json` prints `{"schedules": [...]}` rather than a bare list.
- Due decisions also report `deferred` and the transactions they posted.
- `scheduled --post --json` answers `{"posted": N, "transactions": [...]}`.

Other commands' output is unchanged. Scripts that read the old due-review list
need to read `schedules`.

## Native-book compatibility

No schema change. A book gains a permanent id (`book.id` metadata) the first time it
is opened for writing, and new transactions are stored in the shorter form; every
earlier version reads both. Users, roles, sessions, and each person's own views are
kept in the computer account's user directory, never in the book, so a copied book
carries no one's access.

## Security

Before this release the shared server was reviewed end to end, and its six findings
were fixed: attached documents are never served as something that can run,
sign-in throttling and single-use codes hold for attempts sent together, a change
stream ends once its caller may no longer read, the client never sends a token in
the clear to another computer or to an address a server record could not have
named, and responses are not cached. Decision 0004 records the review and the risks
it accepted. A proxy must set `Host` to the loopback address, overwrite
`X-Real-IP`, and serve only over TLS.

## Upgrade and rollback

Keep an independent backup of a real book. Going back to 0.2.0a307 needs no
restore: the book opens unchanged, though sharing, users, and personal views are
not used there.

## Verified artifacts

After the complete CI matrix succeeds on main, the release workflow publishes a
source distribution, pure-Python wheel, Windows installer, Flatpak bundle, Debian
and Fedora packages, and `SHA256SUMS` for the tested commit.
