# BreadSched 0.2.0a313

Application version: `0.2.0a313`

Native schema version: `13`

Supported native schemas: `6–13`

This alpha fixes three field reports about entering transactions and the desktop's
tables (#404, #406, #407).

## Highlights

- **`.1` is an amount.** No leading zero is needed anywhere an amount is typed.
- **Columns you can arrange.** Drag a desktop table's column headings into the order
  you want (or use the arrows in its column menu); resizing a column widens the
  description, not its neighbour; and the order and widths are remembered.
- **Accounts show balance, value, and price.** Balance in what the account holds,
  value in the reporting currency, the price, and when its quote was last updated.
- **Notes fill in.** Typing a note or memo in the desktop register completes it from
  what you wrote for the same description before.
- **Shares from the checking register.** Buying a fund from checking shows the
  shares and price there, and a split line takes them, in the desktop and browser.
- **No surprise recalculation.** With shares, price, and amount all filled, changing
  one asks which other should change.
- **The register's account list stays on screen** for the transaction at the bottom.

## Command-line and browser compatibility

`GET /api/v1/entry/notes` is new. `/entry/trade` accepts `recompute`. The browser
register's JSON gains `trades`, and its rows carry a cash register's security-leg
`shares` and `price`. Nothing else changes.

## Native-book compatibility

No schema change. Column order and widths are kept with the other view settings on
this computer, not in the book.

## Upgrade and rollback

Keep an independent backup of a real book. Going back to 0.2.0a312 needs no
restore; remembered column orders and widths are ignored there.

## Verified artifacts

After the complete CI matrix succeeds on main, the release workflow publishes a
source distribution, pure-Python wheel, Windows installer, Flatpak bundle, Debian
and Fedora packages, and `SHA256SUMS` for the tested commit.
