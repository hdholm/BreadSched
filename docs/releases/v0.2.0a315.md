# BreadSched 0.2.0a315

Application version: `0.2.0a315`

Native schema version: `14`

Supported native schemas: `6–14`

This alpha builds phase 1 of decision 0005 (#397): an actual counts toward a planned
occurrence by split and amount, so an estimate fills from many purchases.

## Highlights

- **An estimate fills up.** Matching a $120 grocery purchase to a $600 groceries
  estimate counts $120 and leaves $480 expected. Review keeps offering the estimate
  for the month's other purchases, the Projection still counts what remains, and the
  jar is drawn by each purchase. At the end of its period the remainder lapses; a
  late purchase may still be matched to it.
- **The local server's port is its own on Windows.** Another program can no
  longer bind the same port and receive the requests (and tokens) meant for
  BreadSched.
- **Bills behave as before.** A scheduled payment is done once a transaction is
  matched to it or posted from it.

## Command-line and browser compatibility

Planned occurrences in JSON (`breadsched plan-matches` and the browser's Projection
detail) gain `actual_transactions`, `applied_amount`, `remaining_amount`, and
`closed`; Projection detail also lists what remains of a partly met estimate, keyed
`<occurrence>#remaining`. Nothing is removed.

## Native-book compatibility

Schema 14. Opening a schema 13 book migrates it after a verified backup: each
transaction linked to a planned occurrence gains `plan_allocations` on its income,
expense, or planning-purpose legs (its positive legs for a transfer), in full, with
its planned date and amount. Schedules may gain `closed_occurrences`.

## Upgrade and rollback

Keep an independent backup of a real book. 0.2.0a314 and earlier refuse a schema 14
book; to go back, restore the pre-migration backup BreadSched made, which loses
changes made since.

## Verified artifacts

After the complete CI matrix succeeds on main, the release workflow publishes a
source distribution, pure-Python wheel, Windows installer, Flatpak bundle, Debian
and Fedora packages, and `SHA256SUMS` for the tested commit.
