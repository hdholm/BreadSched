# BreadSched 0.2.0a316

Application version: `0.2.0a316`

Native schema version: `14`

Supported native schemas: `6–14`

This alpha builds phase 2 of decision 0005 (#397): Review proposes planned items by
what a transaction was for, and shows what it was for.

## Highlights

- **Category first.** A grocery purchase on the 25th is offered the month's
  groceries estimate before any bill near that date: the same category ranks
  first, then an estimate before a scheduled payment, then the date within the
  item's period, then an amount that fits what remains, then the same funding
  account and description words. The reasons follow the same order, and an
  estimate says how much of it remains.
- **What it was for.** Each actual in Review shows its expense or income accounts,
  the account the money came from, and its notes; the one chosen lists its legs
  with their memos. Desktop, browser, and `breadsched review`.

## Command-line and browser compatibility

`breadsched review --json` adds `categories`, `funding`, and `notes` to each
transaction and `remaining_amount` and `estimate` to each candidate.
`breadsched plan-matches` adds a **remaining** column and, in JSON,
`remaining_amount`, `same_category`, `same_funding`, `in_period`, and `fits`.
`/api/review` and `/api/v1/review` add the same context; candidate order changes as
described. Nothing is removed.

## Native-book compatibility

No schema change.

## Upgrade and rollback

Keep an independent backup of a real book. Going back to 0.2.0a315 needs no
restore.

## Verified artifacts

After the complete CI matrix succeeds on main, the release workflow publishes a
source distribution, pure-Python wheel, Windows installer, Flatpak bundle, Debian
and Fedora packages, and `SHA256SUMS` for the tested commit.
