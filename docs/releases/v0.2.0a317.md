# BreadSched 0.2.0a317

Application version: `0.2.0a317`

Native schema version: `14`

Supported native schemas: `6–14`

This alpha builds phase 3 of decision 0005 (#397): the Match windows, which match
actuals to the plan by split and amount, as a statement is reconciled.

## Highlights

- **From a planned item.** In a Plan value's detail, **Match …** beside a scheduled
  item opens its window: expected, applied, and remaining at the top, and the splits
  in its period below, none checked. Check one to count the amount beside it; type a
  smaller amount to count part. **Close occurrence** lets what remains lapse now.
- **From a transaction.** **Actions → Match to Plan…** in the register, or **Match by
  Split…** in Review, lists each split the transaction was for with the planned items
  it could count toward, best first, so one receipt can count toward two estimates.
  A split can be marked **Not planned**.
- **Command line.** `breadsched plan-allocate` and `breadsched plan-close`.

## Command-line and browser compatibility

New commands `plan-allocate` and `plan-close`. New `/api/v1` routes:
`GET /plan/matching` (`occurrence`), `GET /transactions/{handle}/matching`,
`POST /transactions/{handle}/splits/{split}/allocations` (`occurrence`, `amount`) and
`/not-planned` (`not_planned`), and `POST /plan/occurrences/close` and `/reopen`
(`occurrence`). The browser's windows come in a later alpha. Nothing is removed.

## Native-book compatibility

No schema change. A split marked not planned stores `not_planned`; 0.2.0a316 reads
the book and ignores it.

## Upgrade and rollback

Keep an independent backup of a real book. Going back to 0.2.0a316 needs no
restore; a split marked not planned there counts as unmatched again.

## Verified artifacts

After the complete CI matrix succeeds on main, the release workflow publishes a
source distribution, pure-Python wheel, Windows installer, Flatpak bundle, Debian
and Fedora packages, and `SHA256SUMS` for the tested commit.
