# BreadSched 0.2.0a318

Application version: `0.2.0a318`

Native schema version: `14`

Supported native schemas: `6–14`

This alpha completes the Match to Plan windows of decision 0005 (#397): they open
from every place a planned item is shown, in the desktop application and the
browser.

## Highlights

- **Match… everywhere.** In the desktop application, Scheduled and Upcoming have a
  **Match…** button, and so does every scheduled jar in Budget jars. In the browser,
  **Match…** is on each schedule and beside each scheduled item in a Plan value's
  detail, **Match to plan…** on each register row, and **Match by split…** in Review.
- **What still needs matching.** The Plan's **Resolve actuals (N)…** counts the
  actuals in its range not yet matched.
- **The rest of a split.** **Match** in the window from a transaction adds to what
  the split already counts toward that item, and Review keeps offering an item a
  transaction counts toward only in part.

## Command-line and browser compatibility

Each schedule in `/api/scheduled` adds `current_occurrence`. Nothing is removed.

## Native-book compatibility

No schema change.

## Upgrade and rollback

Keep an independent backup of a real book. Going back to 0.2.0a317 needs no
restore.

## Verified artifacts

After the complete CI matrix succeeds on main, the release workflow publishes a
source distribution, pure-Python wheel, Windows installer, Flatpak bundle, Debian
and Fedora packages, and `SHA256SUMS` for the tested commit.
