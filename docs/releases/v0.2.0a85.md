# BreadSched 0.2.0a85

Application version: `0.2.0a85`

Native schema version: `7`

Supported native schemas: `6–7`

This alpha completes the 0223–0225 service-boundary, commodity-amount, precision,
native-compatibility, and release-discipline milestone work.

## Highlights

- Transaction, account, schedule, assumption, loan, reconciliation, plan, review,
  claim, scenario, and import writes now share explicit service contracts across GTK,
  web, and CLI callers.
- Formula evaluation is resource-bounded and stable error codes cross presentation
  boundaries without exposing engine prose.
- Commodity-tagged amounts now protect transaction values, account quantities,
  ledger aggregation, and dated valuation from accidental mixed-currency arithmetic.
- Declared commodity precision replaces hard-coded cents in scheduled posting,
  Projection, loans, Dashboard, inference, and historical estimates.
- Version and verification diagnostics report both the application build and native
  schema compatibility window.

## Native-book compatibility

Schema 7 books open directly. Schema 6 books are accepted by writable opens and are
migrated sequentially to schema 7 after BreadSched creates and verifies one
`.pre-migration-v6.bak` backup. Read-only schema 6 opens explain that a writable
migration is required. Books older than schema 6 or newer than schema 7 are rejected
explicitly rather than guessed.

No data-format change was made for this release: application alpha increments from
the milestone do not alter native schema 7.

## Upgrade and rollback

Make an independent backup before upgrading. Opening an existing schema 7 book does
not migrate it, so rollback to an earlier BreadSched build that supports schema 7 is
possible without a format conversion. Opening a schema 6 book writable upgrades it to
schema 7; keep the generated `.pre-migration-v6.bak` if rollback to a schema-6-only
build is required. Do not use a synchronized or network filesystem as the only copy
of a live SQLite book.

## Verified artifacts

The release workflow publishes a source distribution, a pure-Python wheel, and
`SHA256SUMS`. It builds from the exact accepted `main` commit only after the full CI
matrix succeeds, installs the wheel outside the source tree, and checks the installed
version/schema report before attaching artifacts.
