# BreadSched 2026.11.18.0

The second beta of BreadSched, a household finance application for tracking your
bank and card accounts, seeing the cash you will have, budgeting with jars,
reporting on where the money goes, and planning years ahead. This beta lets you
arrange the Dashboard. The website, <https://hdholm.github.io/BreadSched/>, walks
through each step.

Application version: `2026.11.18.0`
Release stage: beta (a GitHub pre-release)
Native schema version: `14`
Supported native schemas: `13–14`

## What is new since 2026.11.11.0

- **Arrange the Dashboard.** Each Dashboard item is now a tile on a grid four
  columns wide. **Arrange Dashboard** on the desktop (a toolbar icon and the
  Actions menu) or **Arrange** in the browser places and sizes them:
  - drag an item by its title to move it;
  - drag its corner to make it 1 to 4 columns wide and 1 to 8 rows tall;
  - hide it, or add a hidden one back;
  - put every item back with **Reset Layout**.

  Its arrows and size controls do the same from the keyboard. Items pack from the
  top left, so a small one fills a gap a larger one leaves, and a chart is drawn at
  its tile's size. A narrower window has fewer columns, and a phone stacks the same
  items in the same order. **Done** saves the arrangement as your own, like the
  rest of your Dashboard settings, and the printed Dashboard follows its order.
- An add-on's dashboard breadlet can name the size it starts at.
- For contributors: the development requirements now ask for mypy 1.18.1 or later,
  the oldest that passes both type checks.

The full list is in the [changelog](https://github.com/hdholm/BreadSched/blob/main/CHANGELOG.md).

## Changes to what you do

- **The Dashboard is laid out in tiles.** Until you arrange it, the summary figures
  and the cash-flow chart run across the top and the lists sit two by two below; the
  browser used to stack every item down the page. Each item now has a fixed height,
  so a long list (many pending bills, say) scrolls inside its tile instead of
  growing the page. Make that item taller with **Arrange**.
- Rows and figures on the Dashboard do not open what they name while you are
  arranging it. Choose **Done** or **Cancel** first.

## Upgrade and rollback

Books are unchanged (native schema 14), and this version opens every book the
first beta does: books written by 0.2.0a301 and later (native schemas 13 and 14).
A schema 13 book is brought forward to schema 14 when it is first opened for
writing, after a verified backup is written beside it. A book from an alpha before
0.2.0a301 is refused with a message saying so: open it once with 0.2.0a321, which
brings it forward, then open it here.

Installing over 2026.11.11.0 or an alpha replaces the program and keeps your books;
uninstalling never removes a book. Back up your book before upgrading
(**File → Back Up Current Book…** or `breadsched backup`), and keep the backup until
you are satisfied.

To roll back, install 2026.11.11.0 again: it opens the same books. It ignores the
Dashboard arrangement and shows the items in their own order. Saving
**Configure Dashboard** in it forgets the arrangement, so arrange the Dashboard
again after coming back.

## Verified artifacts

The release workflow builds every file from the tested commit of `main` and attaches:

- the wheel and source distribution;
- `BreadSched-2026.11.18.0-setup.exe`, the per-user Windows installer with its own
  Python and GTK runtime. It is built, installed over the first beta's installer,
  exercised, and uninstalled on Windows;
- `BreadSched-2026.11.18.0.flatpak`, built and installed in its sandbox;
- `breadsched_2026.11.18.0_all.deb` and `breadsched-2026.11.18.0-1.noarch.rpm`,
  built and installed on their distributions;
- `SHA256SUMS` covering all of them.

**These files are not yet code-signed.** Windows SmartScreen may warn before the
installer runs. Check each download against `SHA256SUMS` before installing:

```bash
sha256sum --check --ignore-missing SHA256SUMS
```

On Windows PowerShell, compare `Get-FileHash .\BreadSched-2026.11.18.0-setup.exe`
with its line in `SHA256SUMS`.
