# BreadSched 2026.11.22.1

The fourth beta of BreadSched, a household finance application for tracking your
bank and card accounts, seeing the cash you will have, budgeting with jars,
reporting on where the money goes, and planning years ahead. This beta makes
entering things work the same way everywhere: one transaction editor, schedules
typed like transactions, and every desktop window laid out alike. Finishing a
credit card statement now offers to pay it. The website,
<https://hdholm.github.io/BreadSched/>, walks through each step.

Application version: `2026.11.22.1`
Release stage: beta (a GitHub pre-release)
Native schema version: `15`
Supported native schemas: `13–15`

## What is new since 2026.11.22.0

- **One transaction editor, typed like the register.** New Transaction, a
  register's Edit, reconciliation, and the posted review window all open the same
  editor, its splits typed on the register's own grid.
- **Schedules are entered like transactions on the desktop.** The schedule editor
  types its splits on that grid, with any number of splits. Its number, notes, tags,
  and documents are there too, and every transaction it posts carries them. A
  scenario estimate is edited in the same editor.
- **Finishing a credit card statement offers to pay it**, on the desktop and in the
  browser. The payment opens ready to change. Paying the whole statement settles the
  next payment due. Paying less asks once for the statement's minimum payment: at
  or above it the due is settled; below it the rest of the statement stays due.
- **A bill paid by hand is not offered for posting again.** The due review skips a
  scheduled payment already paid, and offers one partly paid for what remains.
- **Every desktop window looks and answers the same way**: the same margins,
  **Help** at the top, and one row of buttons at the bottom right in the same order,
  the main one last.
- **Reconciling:**
  - A statement line takes its own date and any splits.
  - Changing a reconciled split asks first, at the first keystroke.
  - **Finish** works in the browser, where it had stayed disabled.
- **Registers:**
  - **Blank** (and **Ctrl+End** or **Shift+Page Down**) goes to the new
    transaction.
  - A note or memo completes from the start of a word (`ch` finds "Christmas",
    never "which"), and text you delete from it stays deleted.

The full list is in the [changelog](https://github.com/hdholm/BreadSched/blob/main/CHANGELOG.md).

## Changes to what you do

- **Reconcile's Postpone is now Close**, which still keeps the statement to resume;
  **Abandon** no longer has an ellipsis.
- **Print…** is in each report's bottom row of buttons, beside **Close**, and Find's
  **Find** button is at the bottom of its window.
- **Decide later**, in the due review and held imports, is now **Close**.
- Some button labels are in sentence case: **Choose lots…**, **Realized gains…**,
  **Reset layout**, **Open report**, **Change it**. Menu items keep their names.
- The schedule editor no longer has category, funding, and amount fields: type the
  splits on its grid instead.

## Upgrade and rollback

This version moves books to native schema 15, so that a schedule can keep its
number, notes, and documents, and a card statement its minimum payment. A book is
moved when it is first opened for writing, after a verified backup is written beside
it (`.pre-migration-v14.bak`). It opens every book the earlier betas do: books
written by 0.2.0a301 and later (native schemas 13, 14, and 15). A book from an alpha
before 0.2.0a301 is refused with a message saying so: open it once with 0.2.0a321,
which brings it forward, then open it here.

Installing over 2026.11.22.0, an earlier beta, or an alpha replaces the program and
keeps your books; uninstalling never removes a book. Back up your book before
upgrading (**File → Back Up Current Book…** or `breadsched backup`), and keep the
backup until you are satisfied.

**2026.11.22.0 cannot open a book once it has moved to schema 15.** To roll back,
install 2026.11.22.0 again and open the backup written when the book moved (or your
own backup from before upgrading). Changes made since the move are not in that
backup.

## Verified artifacts

The release workflow builds every file from the tested commit of `main` and attaches:

- the wheel and source distribution;
- `BreadSched-2026.11.22.1-setup.exe`, the per-user Windows installer with its own
  Python and GTK runtime. It is built, installed over the previous beta's
  installer, exercised, and uninstalled on Windows;
- `BreadSched-2026.11.22.1.flatpak`, built and installed in its sandbox;
- `breadsched_2026.11.22.1_all.deb` and `breadsched-2026.11.22.1-1.noarch.rpm`,
  built and installed on their distributions;
- `SHA256SUMS` covering all of them.

**These files are not yet code-signed.** Windows SmartScreen may warn before the
installer runs. Check each download against `SHA256SUMS` before installing:

```bash
sha256sum --check --ignore-missing SHA256SUMS
```

On Windows PowerShell, compare `Get-FileHash .\BreadSched-2026.11.22.1-setup.exe`
with its line in `SHA256SUMS`.
