# BreadSched 2026.11.26.0

The sixth beta of BreadSched, a household finance application for tracking your
bank and card accounts, seeing the cash you will have, budgeting with jars,
reporting on where the money goes, and planning years ahead. This beta makes a
scheduled transaction's future changes versions of the whole transaction, lets you
choose how the desktop shows dates, gathers the desktop's settings in Preferences,
and starts an FSA claim from a transaction you already recorded. The website,
<https://hdholm.github.io/BreadSched/>, walks through each step.

Application version: `2026.11.26.0`
Release stage: beta (a GitHub pre-release)
Native schema version: `16`
Supported native schemas: `13–16`

## What is new since 2026.11.25.0

- **A schedule's changes are versions of the whole transaction.** The schedule
  editors' **Future changes** has one versions editor in place of future,
  per-leg, seasonal, and one-time amounts. A version is every leg of the
  transaction, typed as a register's splits, from a date on, on one date only, or
  every year in one month, so a change can add a leg, drop one, or change any
  amount. An amount may be a formula over `base` (the leg's amount before the
  version) and `base_total`; a new month version starts as every leg `base * 1.0`.
  The desktop, the browser, scenario schedules, and the new `breadsched
  scheduled-versions` command all edit them. A pay change is saved as a version.
- **Choose how the desktop shows dates.** Every desktop date follows your
  computer's locale by default, or `2026-03-15`, `03/15/2026`, `15/03/2026`, or
  `15.03.2026`, chosen in **Edit → Preferences**. Every desktop date field reads
  dates as the register does.
- **Desktop settings are all in Edit → Preferences.** A **Dashboard** tab holds
  what Configure Dashboard held; an account chosen for a group but not added is
  asked about before saving.
- **Track a transaction as an FSA claim**, from a desktop or browser register row
  or `breadsched claims --draft`/`--track`, with its defaults explained.
- **A Dashboard group holding a sub-account of another group's account now
  shows**, each account counted once.
- **Saving an FSA claim on the desktop shows that it took**: **Save claim** is
  greyed out until the form changes, and again once it is saved.

The full list is in the [changelog](https://github.com/hdholm/BreadSched/blob/main/CHANGELOG.md).

## Upgrade and rollback

This version moves books to native schema 16. A book from 2026.11.25.0 or
2026.11.22.1 (schema 15), or from an earlier beta (schemas 13 and 14), is moved to
schema 16 when first opened for writing, after a verified backup is written beside
it (`.pre-migration-v15.bak` for a schema-15 book). The move keeps each schedule's,
and each scenario schedule's, future, per-leg, seasonal, and one-time amounts as
versions with the same amounts. One result differs: a seasonal month amount used to
stop once a later whole-schedule amount change took effect; as a month version it
keeps applying on top of it. Check a schedule that has both after upgrading. A book
from an alpha before 0.2.0a301 is refused with a message saying so: open it once
with 0.2.0a321, which brings it forward, then open it here.

Installing over 2026.11.25.0, an earlier beta, or an alpha replaces the program and
keeps your books; uninstalling never removes a book. Back up your book before
upgrading (**File → Back Up Current Book…** or `breadsched backup`), and keep the
backup until you are satisfied.

To roll back to 2026.11.25.0 or earlier, install it again and open the backup
written when the book moved to schema 16 (or your own backup from before then):
those versions cannot open a schema-16 book, and changes made since the move are not
in that backup.

## Verified artifacts

The release workflow builds every file from the tested commit of `main` and attaches:

- the wheel and source distribution;
- `BreadSched-2026.11.26.0-setup.exe`, the per-user Windows installer with its own
  Python and GTK runtime. It is built, installed over the previous beta's
  installer, exercised (including its Start-menu shortcut, Apps entry, and window
  icon), and uninstalled on Windows;
- `BreadSched-2026.11.26.0.flatpak`, built and installed in its sandbox;
- `breadsched_2026.11.26.0_all.deb` and `breadsched-2026.11.26.0-1.noarch.rpm`,
  built and installed on their distributions;
- `SHA256SUMS` covering all of them.

**These files are not yet code-signed.** Windows SmartScreen may warn before the
installer runs. Check each download against `SHA256SUMS` before installing:

```bash
sha256sum --check --ignore-missing SHA256SUMS
```

On Windows PowerShell, compare `Get-FileHash .\BreadSched-2026.11.26.0-setup.exe`
with its line in `SHA256SUMS`.
