# BreadSched 2026.11.27.0

The seventh beta of BreadSched, a household finance application for tracking your
bank and card accounts, seeing the cash you will have, budgeting with jars,
reporting on where the money goes, and planning years ahead. This beta makes a
scheduled transaction's versions easier to edit on the desktop and tidies the
desktop FSA claims window. The website, <https://hdholm.github.io/BreadSched/>,
walks through each step.

Application version: `2026.11.27.0`
Release stage: beta (a GitHub pre-release)
Native schema version: `16`
Supported native schemas: `13–16`

## What is new since 2026.11.26.0

- **A version's legs are edited without being forced.** In the desktop schedule
  editors' **Future changes**, clearing a leg's account to leave the leg out no
  longer pulls the cursor back to that cell on every key, so another leg's amount
  can be changed first, and Tab and the arrow keys go where they are pressed. An
  account cell still takes only an account that exists, or none; an amount that
  does not work out yet can be left and corrected later, and another version can be
  chosen meanwhile, keeping what was typed. A leg whose cells are all cleared is left
  out. Until every version reads, the status names the first that does not and
  **Save** waits; **Enter** on the grid shows it with the cursor on the line to
  correct.
- **The desktop FSA claims window shows what a claim holds first.** **Healthcare
  payments**, **Provider refunds / credits**, and **FSA allocations** each have an
  arrow, closed when the window opens, so each section lists only the claim's linked
  transactions and allocations. Opening a section adds its search, the transactions
  to add from, and **Add allocation**.

The full list is in the [changelog](https://github.com/hdholm/BreadSched/blob/main/CHANGELOG.md).

## Upgrade and rollback

This version keeps native schema 16, so it changes nothing in a book that
2026.11.26.0 has opened. A book from 2026.11.25.0 or 2026.11.22.1 (schema 15), or
from an earlier beta (schemas 13 and 14), is moved to schema 16 when first opened for
writing, after a verified backup is written beside it (`.pre-migration-v15.bak` for
a schema-15 book). That move keeps each schedule's future, per-leg, seasonal, and
one-time amounts as versions with the same amounts; a seasonal month amount now keeps
applying after a later whole-schedule amount change. A book from an alpha before
0.2.0a301 is refused with a message saying so: open it once with 0.2.0a321, which
brings it forward, then open it here.

Installing over 2026.11.26.0, an earlier beta, or an alpha replaces the program and
keeps your books; uninstalling never removes a book. Back up your book before
upgrading (**File → Back Up Current Book…** or `breadsched backup`), and keep the
backup until you are satisfied.

To roll back to 2026.11.26.0, install it again: it opens the same books. To roll back
further, to 2026.11.25.0 or earlier, open the backup written when the book moved to
schema 16 (or your own backup from before then); changes made since the move are not
in that backup.

## Verified artifacts

The release workflow builds every file from the tested commit of `main` and attaches:

- the wheel and source distribution;
- `BreadSched-2026.11.27.0-setup.exe`, the per-user Windows installer with its own
  Python and GTK runtime. It is built, installed over the previous beta's
  installer, exercised (including its Start-menu shortcut, Apps entry, and window
  icon), and uninstalled on Windows;
- `BreadSched-2026.11.27.0.flatpak`, built and installed in its sandbox;
- `breadsched_2026.11.27.0_all.deb` and `breadsched-2026.11.27.0-1.noarch.rpm`,
  built and installed on their distributions;
- `SHA256SUMS` covering all of them.

**These files are not yet code-signed.** Windows SmartScreen may warn before the
installer runs. Check each download against `SHA256SUMS` before installing:

```bash
sha256sum --check --ignore-missing SHA256SUMS
```

On Windows PowerShell, compare `Get-FileHash .\BreadSched-2026.11.27.0-setup.exe`
with its line in `SHA256SUMS`.
